# Распределение заявок с помощью Q-learning

Учебный проект по обучению с подкреплением: агент учится направлять заявки одному из трёх операторов с разной скоростью обработки. Среда моделирует обслуживание, а табличный Q-learning оценивает действия по завершённым заявкам, текущей нагрузке и отказам.

В проекте реализованы обучение, сравнение с простыми стратегиями, графики и пошаговая демонстрация. В сохранённом эксперименте агент получил более высокую награду, чем Random и Least Loaded, но уступил стратегии «самый быстрый доступный».

## Быстрый старт

Нужен **Python 3.10 или новее**. Все команды выполняются из корня репозитория.

```bash
git clone https://github.com/Xenia-Golb/rl-request-scheduling.git
cd rl-request-scheduling
python3 -m venv .venv
```

Активируйте окружение:

```bash
# macOS / Linux
source .venv/bin/activate
```

```powershell
# Windows PowerShell
.venv\Scripts\Activate.ps1
```

Установите зависимости:

```bash
python -m pip install -r requirements.txt
```

В `results/` уже есть обученная Q-таблица. Чтобы сразу увидеть решения агента:

```bash
python main.py --demo
```

Для полного запуска с новым обучением:

```bash
python main.py
```

По умолчанию выполняются **10 000 эпизодов обучения**, оценка четырёх стратегий по **1000 эпизодов** и построение графиков. Каждый эпизод содержит 100 шагов. Результаты сохраняются в `results/`, графические окна не открываются.

**Повторный запуск перезаписывает создаваемые им файлы.** Для отдельного эксперимента используйте `--output-dir`.

## Режимы запуска

| Команда | Что выполняется |
|---|---|
| `python main.py` | Обучение, оценка четырёх стратегий и все графики |
| `python main.py --demo` | Загрузка Q-таблицы, вывод 100 шагов в терминал и визуализация эпизода |
| `python main.py --visualize` | График загрузки и карта решений по сохранённой Q-таблице |

В режимах `--demo` и `--visualize` агент действует без случайного исследования и не обновляет Q-таблицу. При равных максимальных Q-значениях он выбирает случайно среди лучших действий.

Другой демонстрационный эпизод:

```bash
python main.py --demo --demo-seed 200001
```

Короткий проверочный запуск в отдельной папке, затем просмотр его результатов:

```bash

python main.py --demo --output-dir results/smoke
```

20 эпизодов достаточно для проверки запуска, но не для вывода о качестве обучения. В режиме демонстрации `--output-dir` также задаёт папку, из которой загружается `q_table.npy`.

Команда `python -m src.evaluate` использует стандартную папку `results/`. Для оценки таблицы из другой папки можно вызвать функцию:

```bash

```

## Как устроена среда

На каждом шаге поступает **одна новая заявка**. Каждый оператор может одновременно обрабатывать до трёх заявок.

| Оператор | Вероятность завершения каждой заявки за шаг | Среднее число проверок до завершения |
|---|---:|---:|
| №1 — быстрый | 1/2 | 2 |
| №2 — средний | 1/4 | 4 |
| №3 — медленный | 1/6 | 6 |

**Состояние** — кортеж загрузок `(n₁, n₂, n₃)`. Например, `(2, 0, 1)` означает две заявки у первого оператора, свободного второго и одну заявку у третьего. Каждая загрузка принимает значения от 0 до 3: всего `4³ = 64` состояния.

**Действие** — индекс оператора: `0`, `1` или `2`. В терминале и на графиках операторы обозначаются привычными номерами **№1, №2, №3**.

Шаг среды выполняется в следующем порядке:

1. Новая заявка назначается выбранному оператору. Если он уже занят тремя заявками, новая заявка отклоняется.
2. Каждая активная заявка, включая только что поступившую, независимо может завершиться с вероятностью своего оператора.
3. По оставшейся загрузке вычисляются следующее состояние и награда.

Отдельной очереди ожидания нет. Завершение заявок происходит после назначения, поэтому отказ возможен даже тогда, когда выбранный оператор освободится на этом же шаге.

### Награда

```text
reward = completed − 0.1 × remaining_load − rejected
```

Здесь `completed` — число завершённых заявок за шаг, `remaining_load` — суммарная загрузка после обработки, `rejected` — 1 при отказе и 0 иначе. Агент стремится увеличить суммарную дисконтированную награду; равномерная загрузка сама по себе не является целью.

### Граница эпизода

Через 100 шагов среда возвращает `done=True`. Перед следующим эпизодом загрузка сбрасывается. Время до конца эпизода не входит в состояние.

В обучении этот лимит трактуется как обрыв наблюдения непрерывной задачи: на последнем шаге сохраняется оценка будущей награды (*bootstrap*). Поэтому `train.py` передаёт в обновление `done=False`. Метод `agent.update(..., done=True)` поддерживает настоящий терминальный переход без будущей награды, но в текущем цикле обучения он не используется.

## Алгоритм Q-learning

Q-таблица содержит **64 строки × 3 действия**. Индекс состояния:

```python
state_index = state[0] * 16 + state[1] * 4 + state[2]
```

Обновление оценки после действия:

```text
Q(s, a) ← Q(s, a) + α × [r + γ × max Q(s′, a′) − Q(s, a)]
```

При обучении используется epsilon-greedy: с вероятностью ε выбирается случайный оператор, иначе — действие с максимальным Q. После каждого эпизода ε уменьшается. Все действия доступны, в том числе выбор заполненного оператора: агент учится на штрафах за отказ.

Основные настройки находятся в `config.py`:

| Параметр | Значение |
|---|---:|
| Эпизоды обучения | 10 000 |
| Шаги в эпизоде | 100 |
| Скорость обучения α | 0,1 |
| Коэффициент дисконтирования γ | 0,95 |
| Начальное / минимальное ε | 1,0 / 0,01 |
| Множитель уменьшения ε за эпизод | 0,995 |
| Seed обучения | 42 |
| Эпизоды оценки на стратегию | 1000 |

## Оценка и реальные результаты

При оценке Q-таблица не меняется, случайное исследование отключено. Стратегии сравниваются на новых эпизодах с seed от `100000`; случайный выбор действий использует отдельный генератор. Список seed одинаков для всех стратегий, но число активных заявок различается, поэтому последовательности событий не обязаны совпадать.

| Стратегия | Правило выбора |
|---|---|
| Random | Случайный оператор, включая заполненных |
| Least Loaded | Минимальная загрузка; при равенстве — случайный выбор |
| Q-learning | Максимальное Q-значение; при равенстве — случайный выбор |
| Fastest Available | Самый быстрый незаполненный оператор; если заполнены все — самый быстрый |

Сохранённый результат после 10 000 эпизодов обучения, средние значения по 1000 эпизодам оценки:

| Стратегия | Награда ↑ | Завершено заявок ↑ | Отклонено заявок ↓ |
|---|---:|---:|---:|
| Random | 59,274 | 91,359 | 5,956 |
| Least Loaded | 74,643 | 97,664 | 0,001 |
| Q-learning | 84,877 | 98,596 | 0,014 |
| Fastest Available | 88,482 | 98,914 | 0,000 |

Источник: `results/evaluation_summary.csv`. Значения относятся к одному эпизоду из 100 шагов, а не ко всему тестированию.

Q-learning превосходит Random и Least Loaded по награде и числу завершений. Least Loaded реже отклоняет заявки, а Fastest Available получает более высокую награду, чем обученный агент. Это результат одного обучения; для устойчивого сравнения нужны повторные запуски с разными seed обучения.

`main.py` оценивает все **четыре** стратегии и сохраняет подробную историю со сводкой. `python -m src.evaluate` формирует отдельную таблицу **трёх** стратегий для лабораторной — `evaluation.csv`. Эти файлы создаются разными командами: после нового обучения отдельно обновите `evaluation.csv`, если используете его в отчёте.

## Визуализация действий агента

### Динамика обучения

Светлая линия — награда каждого эпизода, тёмная — скользящее среднее по 100 эпизодам. Это награды меняющейся политики во время обучения; они могут отличаться от оценки итоговой таблицы.

![Награда за эпизод и скользящее среднее](results/training_reward.png)

### Загрузка операторов

Показан один полный эпизод с seed `200000`. Шаг 0 — начальное состояние, последующие точки — загрузка после обработки. График отражает число активных заявок, а не число назначений.

![Загрузка трёх операторов за эпизод](results/operator_loads.png)

### Карта решений

Четыре панели фиксируют загрузку третьего оператора от 0 до 3. Горизонтальная ось — загрузка второго, вертикальная — первого. В ячейках указаны номера операторов с максимальным Q-значением. При равенстве перечислены все варианты.

![Карта решений для 64 состояний](results/decision_map.png)

Карта включает все 64 состояния, в том числе редкие. Равные или нулевые оценки не доказывают, что состояние посещалось: счётчики посещений не сохраняются. Политика также может выбирать заполненного оператора — оптимальность после заданного числа эпизодов не гарантирована.

`.npy` — бинарный формат NumPy, его не нужно открывать как текст. Посмотреть таблицу целиком:

```bash
python -c "import numpy as np; q = np.load('results/q_table.npy', allow_pickle=False); print('Размер:', q.shape); print(q)"
```

Или получить оценки для конкретного состояния:

```python
from src.agent import QLearningAgent

agent = QLearningAgent()
agent.load('results/q_table.npy')
state = (2, 0, 1)
print(agent.q_table[agent.state_index(state)])
print('Выбран оператор №', agent.choose_action(state, explore=False) + 1)
```

Q-значение — оценка будущей дисконтированной награды, а не вероятность выбора оператора.

## Проверка работы

Проверка среды:

```bash
python -c "from src.environment import RequestEnvironment; env = RequestEnvironment(seed=42); print(env.reset()); print(env.step(0))"
```

Ожидаемый вывод для этого seed:

```text
(0, 0, 0)
StepResult(state=(1, 0, 0), reward=-0.1, done=False, completed=0, rejected=False)
```

Проверки алгоритма:

```bash
python -m unittest discover -s tests
```

Тесты проверяют однозначную нумерацию 64 состояний, обновление Q и терминальный переход, выбор действий, нижнюю границу ε и отсутствие обучения при оценке.

Если демонстрация сообщает, что Q-таблица не найдена, сначала выполните `python main.py` или укажите папку с таблицей через `--output-dir`. Если не находятся `numpy` или другие зависимости, проверьте активацию `.venv` и повторите установку через `python -m pip`.

Версии зависимостей в `requirements.txt` ограничены снизу, но не закреплены точно. Seed делает эксперимент воспроизводимым при одинаковом коде и окружении; полное совпадение результатов между разными версиями библиотек не гарантируется.
